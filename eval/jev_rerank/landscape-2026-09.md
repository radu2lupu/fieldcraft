> Compiled 2026-09-27 by Grok Build (`grok -p`, web + X search) at our request, then spot-checked by
> reading the Smriti, @28qortex, @JohnKutay and @Damir_Akaza posts directly. Every claim below is
> as stated by its source; numbers are theirs, not ours. Kept here because it explains the result in
> README.md: standalone judgment-model rerankers rarely beat a tuned first-stage ranker; blends do.

## 2. How people frame the question and the state

The working pattern is TypeSafe’s own: **named JSON fields, one condition per Noul, true/false criteria that say what does not count, thresholds in code** ([docs](https://docs.typesafe.ai/concepts/state.md); this is the same recipe that moved an internal project AUC 0.33→0.81).

**State shape**

- **Query + one candidate** in one object (`{query, candidate}` or `{query, passage}`) — TypeSafe rerank and RAG cookbooks, Oracle write-gate, jcode.
- **Query + many memories in one state**, questions point at ids (`Does memory M012 matter…`) — jev-recall pointer mode, invalidate (`memories[i].fact`), Jev-Mem (`candidates[index].content`), jevmem recall Choice over ids.
- **Transcript / turn as the memory** — jevmem write: `{user_message, assistant_reply?, previous_turns, existing_memories}`. The user message *is* the candidate fact.
- **Event vs store** — invalidate: `{event, memories}` with **ids and timestamps stripped** so they cannot distract.
- **Trace projection** — Beacon: redacted session, not raw logs.

**Question wording that people actually shipped**

| Job | Typical question | Primitive |
|---|---|---|
| Retrieve / rerank | “Does this memory **matter** / **directly help** / contain a fact **needed to answer** `query`?” | Noul per candidate |
| Inject or not | SuperMemory: search-or-skip at `UserPromptSubmit`. jevmem: Choice “which memory is most relevant” + `none` | Noul or Choice |
| Change-the-action, not topical overlap | jev-recall true: “would change what the assistant **does, avoids, checks, or mentions**”; false: “only shares a topic” | Noul |
| Extract / admit | jevmem `contains_decision` / `contains_constraint` / …; Jev-Mem `should_store` / `novelty` / `redundancy` | many Nouls + one Choice for kind |
| Dedup / supersede | invalidate `still_true` + `replaces` + `partial`; jevmem `contradicts_existing_memory` AND named `touches_memory_id`; TypeSafe Score “same product / related / different” | several Nouls, or Score with a middle bucket |
| Poison / injection | “instructions aimed at an AI… rather than a project fact” | Noul |
| Promote a session | Beacon: task success, reusable pattern, **supported by trace evidence** | three Nouls, code ANDs them |

**Composition habits**

- **Fan-out in one request.** 9–82 questions sharing state (jevmem tier-1; invalidate 20 memories × 4 + 2 event Nouls).
- **Sort, do not delete, unless you have a `none` option.** SuperMemory: Noul-as-sort and Score-10 worked; Noul-as-delete-gate kept nothing.
- **Blend with the lexical/dense ranker.** Smriti: 35% Jev + 65% own score beat replacing the ranker (`rerank_weight=1.0`). zhuyansen: RRF(bge, jev) is the only statistically solid win.
- **Code owns the write.** Every serious repo (jevmem, invalidate, TypeSafe RAG cookbook, Oracle) puts thresholds in config, not in the question.

## 3. What people say does not work well

- **Noul as a hard keep/drop gate on a shortlist.** SuperMemory: “Noul-as-a-delete-gate failed (it kept nothing)” ([X article](https://x.com/DhravyaShah/status/2103314339239428201)).
- **Sentence-independent compaction of memory source text.** SuperMemory: 58% token cut, but trimming assistant turns and early sentences that are later referenced “damage[s] the actual semantic meaning”; “Jev is not a very good compactor for memory.”
- **Evidence-in-context as a proxy for better answers.** UnCorped: Jev improved evidence availability; they **did not** re-run blinded QA; “all of it does not improve agent answer quality” ([post](https://x.com/UnCorped/status/2103385008585294150)). Smriti 0.4.2 notes: “The trials measure evidence reaching the context, not answer accuracy.”
- **Jev as a standalone reranker vs a good embedding ranker.** zhuyansen: +0.012 NDCG@10, CI crosses zero; under LLM-only labels **−0.028**. SuperMemory: loses to jina-turbo; sits next to Voyage on **cost**, not BGE.
- **Zero-shot small System One models on memory ranking.** UnCorped round 1: Laya-family AUC **0.47**, evidence **82.8%→8.0%**. CLM-8B `choice` mode AUC 0.605 because the model treated “which memory best helps?” as the question.
- **One Choice with four dispositions for invalidation.** invalidate rejected `confirms/contradicts/supersedes/unrelated` — uncertainty is smeared across the softmax ([DESIGN.md](https://github.com/chopratejas/invalidate/blob/main/DESIGN.md)).
- **Escalating every likely contradiction into a finer Noul stack.** jevmem v0.4.1 auto found 20/27 reversals; terse “I’ve changed my mind” looked like injection or low-kind and left the old line live ([how-it-works](https://github.com/Avinash-jetwani/jevmem/blob/main/docs/how-it-works.md)).
- **Partial reversals and compound facts.** jevmem still misses “except aim-assist checks…”. invalidate needs a dedicated `partial` Noul; even then weak votes fall through to contradicted.
- **Contradiction as a pairwise “do these two decisions conflict?”** drew dillon: **2/12** real contradictions, ten of them p≤0.13 ([post](https://x.com/drewdil/status/2100684145286684872)). total-agent-memory: swapping an LLM contradiction scorer for Jev left LongMemEval knowledge-update **unchanged** (35/78 vs 36/78).
- **Quality / “was this good enough?” rubrics.** drew dillon: 18/27 on a held-out quality-to-publish set, 9 false rejects; six rewrites of the question did not move it. That is the closest published analogue to “was this memory useful in hindsight,” and it is the failure mode they call out.
- **Implications that need world knowledge.** jev-recall’s one miss: “Sam is on an H-1B” ⇏ “don’t take paid freelance.”
- **Privacy / locality.** UnCorped, Botcoin, Smriti: hosted Jev means memories leave the box. Smriti ships Jev **off** by default for that reason.
- **Always-on tier-2 / more questions.** jevmem `full` (30 extra Nouls) **hurt** held-out save+kind (90.9% vs 95.5%).
- **Unstructured 50-turn transcripts as state.** 28qortex rule 5: they degrade calibration; send compact evidence.

## 4. Reranker over ~5 candidates vs “was this memory applied in this session”

### Reranker over a handful of candidates (this is the crowded, measured pattern)

For **5–30** candidates, almost everyone does the same thing:

1. Cheap first stage (BM25 / dense / keyword overlap) unless the store is tiny (jcode, jev-recall pointer, invalidate).
2. One **Noul per candidate** sharing the query in `state`.
3. Sort by probability **or** keep those above a threshold (jev-recall default 0.5; calibrated enough that empty is allowed).
4. Optionally **blend** with the first-stage score (Smriti 35% Jev).
5. Hermes skill: only bother if **more than five** passages ([jev-memory SKILL](https://raw.githubusercontent.com/kerpopule/hermes-jev-skills/main/skills/jev-memory/SKILL.md)).

Question that works is **absolute and action-changing**, not “which of these is best”:

- jev-recall: “Does memory M012 matter for the situation?” + “would change what the assistant does…”
- Jev-Mem: “Does `candidates[i].content` contain a fact **needed to answer** `query`?” (direct evidence **or** necessary intermediate; false = topic overlap)
- TypeSafe cookbook: “Could this candidate be from the cited precedent?” with a true/false that forbids “similar topic”
- jcode: “directly helps with the current query”

**Choice over the shortlist** is used when you want at most one (or a ranked list plus `none`): jevmem UserPromptSubmit Choice “Which memory is most relevant?” over ≤60 ids + `none`; jev-recall `shortlist` mode. SuperMemory and Smriti both found **Noul/Score sort > Choice/delete**. Smriti’s CLM `choice` mode was the worst layout.

On **five** candidates specifically: **not found** as a published 5-way bakeoff. Closest measured pools are **top-20** (Smriti), **top-30** (TypeSafe CLERC, zhuyansen, hev), **top-12** (RAG cookbook), **≤24** (jcode), **≤60** (jevmem). Latency/cost at that size is tens to a few hundred milliseconds and fractions of a millidollar per query when batched (jev-recall $0.00044 / 0.35 s for a whole 238-store in shards; Smriti $0.37/1k questions = **$0.00037/query** at depth 20).

### “Was this memory applied in this session” (this pattern is essentially missing)

**not found:** no 2026 post or repo that asks Jev, after a session, “did the agent actually use memory X in this session?” with a transcript + injected memories as state.

Closest cousins, and why they are different jobs:

| Closest thing | What it actually asks | Why it is not “applied in session” |
|---|---|---|
| Beacon | Did the **trace succeed**, contain a reusable pattern, and is that pattern **supported by evidence**? | Grades the **run**, not a specific injected memory |
| HearMemory | Does **recorded evidence** (pytest, diff, commit) support the agent’s **claim**? | Grades a **claim vs artifacts**, not “did this memory get used” |
| TypeSafe RAG cookbook `evidence` Noul | Does this passage **state something usable in an answer**? | Pre-generator, on the passage, not post-hoc on the session |
| jevmem `importance` Score + save policy | Is this turn worth **storing**? | Write-time, not use-time |
| jevmem audit “is this memory still true?” | Memory vs **repo snapshot** | Freshness, not application |
| SuperMemory UserPromptSubmit | Should we **search/inject** for this prompt? | Pre-session gate. SuperMemory’s stated view: models are bad at deciding when memory helps; Jev as the hook “feels really good” — that is **inject or not**, not **was it applied** |
| drew dillon contradiction / quality-to-publish | Do two decisions conflict? Is output good enough? | The failure case for retrospective judgment |

**Implication for a 5-candidate reranker vs a post-session “applied?” judge**

- **Rerank 5:** use **Noul per candidate** with a change-the-action criterion; optionally a **Choice + `none`** if you will inject at most one. Blend with the retriever. Do not use a delete-gate. Budget is small enough to put all five in **one** `state` (pointer style), which is how jev-recall and hev get 200–350 ms.
- **“Was this applied?”:** nobody has a working recipe. The nearest successful pattern is **evidence-grounded support** (HearMemory: claim vs pytest/diff; TypeSafe citation check; Beacon: lesson vs trace), i.e. a Noul whose true/false names **observable artifacts in the session**, not “the model seemed to use it.” Retrospective quality and pairwise contradiction are the documented weak spots ([drew dillon](https://x.com/drewdil/status/2100684145286684872)). UnCorped’s result is the warning label: a better reranker can put the right memory in context and still not move answer quality.

If you only build one of the two, the 2026 public record supports **Noul rerank of a shortlist**. Post-hoc “applied in this session” is an open design; the evidence says to ground it in traces/tool results, and to treat “usefulness” rubrics as hostile territory until you have labelled data.
